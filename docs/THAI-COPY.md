# THAI-COPY.md: คู่มือภาษาบนหน้าจอ KruScan

ใช้กับทุกข้อความที่ผู้ใช้เห็น ทั้งหน้าเว็บ (frontend) และข้อความแจ้งจาก server (backend error/success) ต่อยอดจาก `DESIGN.md` ข้อ 5 "ใช้ภาษาครู ไม่ใช่ภาษาระบบ"

ผู้อ่านคือ **ครูไทยที่ใช้มือถือระหว่างวัน** น้ำเสียงคือครูคุยกับเพื่อนครู สุภาพ เป็นกันเอง สั้น ตรง ไม่ทางการแบบหนังสือราชการ และไม่ใช่ภาษาแปลจากอังกฤษ

## หลักใหญ่ 6 ข้อ

1. **พูดแบบคน ไม่ใช่แบบเครื่อง**: อ่านออกเสียงแล้วต้องฟังเหมือนครูพูดกันจริง
2. **สั้นที่สุดที่ยังครบความ**: ตัดคำเติมที่ไม่เพิ่มความหมาย
3. **คำเดียวกันสำหรับสิ่งเดียวกันทุกหน้า**: ดูตารางศัพท์ด้านล่าง
4. **ผิดพลาด = เกิดอะไร + ทำอะไรต่อ**: ไม่โทษผู้ใช้ ไม่ใช้ศัพท์โค้ด
5. **ปุ่ม = กริยา (+ สิ่งที่ทำ)**: บอกผลที่จะเกิด เช่น "บันทึก" "เพิ่มนักเรียน" "ลบ 3 รายการ"
6. **ไม่มีภาษาระบบหลุด**: enum, error ภาษาอังกฤษ, ชื่อฟิลด์ในโค้ด ต้องไม่ถึงตาครู

## รูปแบบ

- ไม่ลงท้าย ค่ะ/ครับ ในข้อความหน้าจอ (ยกเว้นข้อความที่ครูคัดลอกไปส่งเอง เช่นข้อความทวงงาน ซึ่งมีตัวเลือกให้แล้ว)
- เว้นวรรคแทนจุลภาค เช่น "บันทึกแล้ว ส่งต่อได้เลย"
- ตัวเลข + หน่วย เว้นวรรค: "20 คน" "3 รายการ"
- ใช้ "…" (อักขระเดียว) ในสถานะกำลังทำ: "กำลังบันทึก…"
- คำถามยืนยันลงท้าย "ใช่ไหม?" ได้
- ไม่ใช้ตัวหนา/อีโมจิประดับในข้อความ
- ห้องว่าง/รายการว่าง: บอกว่านี่คืออะไร ทำไมว่าง ทำอะไรต่อ เช่น "ยังไม่มีงาน กด เพิ่มงาน เพื่อเริ่ม"

## ห้ามแตะ (ไม่ใช่ข้อความหน้าจอ)

- ชื่อตัวแปร คีย์ enum ค่าที่โค้ดเอาไปเทียบ (เช่น `reason === 'QR code already exists'`, `status === 'DONE'`)
- **หัวคอลัมน์ไฟล์นำเข้าตัวอย่าง** และคำที่ parser ใช้จับคอลัมน์ (`rosterImport.js` ฝั่ง backend, template CSV)
- ค่าที่ส่งไป API, key ของ localStorage, path
- ข้อความที่เทสต์ตรวจตรง ๆ (ถ้าแก้ ต้องแก้เทสต์ให้ตรงด้วยและรันผ่าน)
- เนื้อหาเอกสารราชการที่ต้องตรงแบบฟอร์มโรงเรียน (หัวข้อในไฟล์ Word บันทึกหลังแผน) — แก้เฉพาะที่ผิดชัดเจน
